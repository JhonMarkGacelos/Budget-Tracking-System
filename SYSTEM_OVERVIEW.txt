================================================================================
                              SYSTEM OVERVIEW
================================================================================

The Budget Tracking System is a comprehensive Laravel-based application that
manages budget requests, financial submissions, and approvals following a
strict hierarchical workflow:

                    Faculty Submit → Department Review → Admin Approval

================================================================================
                          SYSTEM ARCHITECTURE
================================================================================

HIERARCHICAL USER STRUCTURE:

1. ADMIN (Single Authority)
   - Full access to all system data
   - Creates Department and Faculty users
   - Final approval authority for budget requests
   - Views all submissions and reports

2. DEPARTMENT HEADS (Multiple per Department)
   - Manages their department's faculty
   - Reviews budget requests from their faculty
   - Approves/rejects with feedback
   - Reviews submissions and reports

3. FACULTY/STAFF (Multiple per Department)
   - Submits budget requests
   - Uploads financial documents
   - Submits liquidation reports
   - Views only their own data

DEPARTMENTS (6 Total):
   - College of Graduate Studies
   - College of Nursing and Health Sciences
   - College of Engineering
   - College of Education
   - College of Arts and Sciences
   - College of Industrial Technology

================================================================================
                         WORKFLOW IMPLEMENTATION
================================================================================

BUDGET REQUEST WORKFLOW:

1. Faculty Submits (Status: pending)
   - Faculty creates budget request
   - Request assigned to their department
   - Goes to Department's review queue

2. Department Reviews (Status: department_approved / department_rejected)
   - Department head reviews request
   - Can approve and forward to Admin
   - Can reject with feedback
   - Faculty can modify pending requests

3. Admin Final Approval (Status: admin_approved / admin_rejected)
   - Admin reviews request
   - Final approval authority
   - Can reject at any stage
   - Can provide feedback

SUBMISSION WORKFLOW:

1. Faculty Submits Financial Documents
   - Attach to approved budget request
   - Can upload files
   - Status: pending

2. Department Reviews
   - Reviews submission
   - Provides feedback
   - Status: department_reviewed

3. Admin Reviews
   - Final review
   - Completes process
   - Status: admin_reviewed

================================================================================
                         DATABASE STRUCTURE
================================================================================

USERS TABLE:
  - ID: Primary key
  - Name: User's full name
  - Email: Unique email address
  - Password: Bcrypt hashed
  - Role: admin, department, or faculty
  - Department_ID: Foreign key (nullable for admin)
  - Timestamps

DEPARTMENTS TABLE:
  - ID: Primary key
  - Name: Unique department name
  - Description: Department details
  - Timestamps

BUDGET_REQUESTS TABLE:
  - ID: Primary key
  - User_ID: Faculty member (foreign key)
  - Department_ID: Department (foreign key)
  - Title: Request title
  - Description: Detailed description
  - Amount: Budget amount
  - Status: pending/department_approved/admin_approved/rejected
  - Feedback fields for each level
  - Review timestamps

BUDGET_SUBMISSIONS TABLE:
  - ID: Primary key
  - User_ID: Submitter (foreign key)
  - Budget_Request_ID: Related request (foreign key)
  - Content: Submission details
  - Document_Path: Uploaded file path
  - Status: pending/department_reviewed/admin_reviewed
  - Feedback fields

LIQUIDATION_REPORTS TABLE:
  - ID: Primary key
  - User_ID: Reporter (foreign key)
  - Budget_Request_ID: Related request (foreign key)
  - Content: Report details
  - Document_Path: Uploaded file path
  - Status: pending/department_reviewed/admin_reviewed
  - Feedback fields
